03 / Les verbes HTTP

Quatre actions, un langage commun.

GET

Consulter

Récupérer des informations sans créer de ressource.

/api/menu
POST

Créer

Envoyer une nouvelle commande au serveur.

/api/orders
PUT

Remplacer

Remplacer la représentation d’une ressource.

/api/orders/42
DELETE

Supprimer

Demander la suppression d’une ressource.

/api/orders/42

Chaque méthode exprime une intention. Le serveur décide si la demande est autorisée et valide.

05 / Exemple concret

Ce qui circule vraiment.

Requête · Front → API
POST /api/orders HTTP/1.1
Authorization: Bearer <token>
Content-Type: application/json

{
  "productId": 4521,
  "quantity": 1,
  "paymentMethod": "card"
}
Réponse · API → Front
HTTP/1.1 201 Created
Content-Type: application/json

{
  "orderId": 98213,
  "status": "CONFIRMED",
  "total": 349.90,
  "currency": "EUR"
}

Exemple simplifié : les données et identifiants sont fictifs. En pratique, le paiement peut suivre un parcours distinct.

07 / Une application fiable

Quand tout ne se passe pas comme prévu.

401

Non authentifié

Le serveur refuse la demande : il faut se reconnecter ou fournir un jeton valide.

409

Conflit

Par exemple, le stock a changé. L’interface propose de revoir la commande.

500

Erreur serveur

Une erreur inattendue survient. Le front affiche un message compréhensible.

Bonne expérience utilisateur : confirmer ce qui a réussi, expliquer ce qui a échoué et permettre une action utile.

Conclusion / Complémentarité

Deux expertises. Une expérience.

Front-end · la salle

Donner envie de commander

  • Rendre les fonctionnalités accessibles
  • Guider et rassurer l’utilisateur
  • Présenter des retours immédiats
Back-end · la cuisine

Tenir la promesse

  • Appliquer la logique métier
  • Protéger les accès et les données
  • Assurer la cohérence des opérations

Une belle interface sans fonctionnalités fiables ne suffit pas. Un serveur performant sans expérience utilisable non plus.

Le but ultime

Rendre le complexe simple à vivre.

Derrière chaque clic se cache une collaboration : interface, API, règles métier et données. L’utilisateur, lui, ne devrait voir qu’une expérience fluide.
